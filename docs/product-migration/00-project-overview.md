# 00 — Project Overview (전환 중)

> **상태:** 개요·방향 합의용. 이 문서만으로 코드를 지우거나 대규모 리팩터를 시작하지 않는다.  
> **작업 순서:** 분석 → 분류 → 설계 → 마이그레이션 계획 → (승인 후) 코드 수정.  
> **상세:** `01`–`11`이 이미 있으면 이 개요가 상위 요약이고, 충돌 시 **재사용·비삭제** 원칙을 우선한다.

---

## 0. 전환 원칙 (가장 중요)

이 프로젝트는 **처음부터 다시 만드는 작업이 아니다.**

1. **먼저** 현재 구현(기능·코드·데이터·파이프라인)을 전체적으로 분석한다.
2. 새 제품에 필요한 것은 **최대한 재사용**한다.
3. 필요 없는 것은 **삭제보다 숨김/비활성화/나중 정리**를 기본으로 한다.
4. 임의로 대규모 코드를 지우거나, 기존 기능을 “새 방향이니까” 무조건 폐기하지 않는다.
5. **분석 → 분류(Keep / Modify / Defer / Remove) → 설계 → 마이그레이션 계획**을 문서화한 뒤에야 코드를 바꾼다.

관련 문서: `01-current-architecture.md`, `02-keep-modify-remove.md`, `11-implementation-plan.md`.

## 1. 제품이 어디서 어디로 가는가

### 현재 (Market Radar)

AI가 금융시장 정보를 수집·분석해, 사용자가 **읽을 브리핑 / Signal**을 제공한다.

```text
Sources → Ingest → Cluster → LLM → Signal / Brief → App (읽기·듣기)
```

성공 감각(기존): *“오늘 내가 알아야 할 것을 이미 찾아놨다.”*

### 목표 (Issue + Participation)

AI가 인터넷에서 **사람들이 관심을 갖는 이슈**를 발견하고,  
짧고 이해하기 쉬운 **카드**로 구조화한 뒤,  
사용자가 **의견을 표현**하고 다른 사람과 **가볍게 참여**할 수 있게 한다.

```text
Information → AI Issue → Card → Participation
```

성공 감각(목표): *“이 이슈, 어떻게 생각해? — 한 번 누르고 남들 의견도 본다.”*

### 무엇이 아닌가

| 아님 | 이유 |
|------|------|
| AI 뉴스 요약 앱 | 요약이 끝이 아니라 **참여**가 핵심 |
| 금융 대시보드 / HTS | 차트·호가·필터 밀도가 아님 |
| 거대한 SNS | 팔로우·DM·친구 그래프는 MVP 밖 |
| Prediction Market / 실물 베팅 | 돈·정산·마켓 메이킹 없음 |
| X 리포스트 봇 | 원문 나열이 제품이 아님 |

## 2. 핵심 사용자 경험 (MVP)

앱을 열면 복잡한 금융 UI가 아니라 **이슈 카드 피드**가 보인다.

### 카드가 담는 것 (예시 구조)

1. **훅 헤드라인** — 사람들이 궁금해할 한 문장  
   예: *NVIDIA Blackwell 수요, 계속 강할까?*
2. **짧은 배경** — 왜 지금 이슈인지 2–4문장
3. **핵심만 보면** — 불릿 몇 개 (사실·변수 정리)
4. **사람들이 궁금해하는 것** — 한 줄 질문
5. **당신의 생각은?** — 원탭 선택  
   예: 계속 강할 것 같다 / 둔화될 것 같다
6. **참여 규모** — *1,824명 참여* + (투표 후) 비율·다른 의견·댓글

### MVP에서 완성할 루프

```text
이슈 카드 본다 → 이해한다 → 의견 한 번 누른다 → 집계·타인 의견·댓글을 본다
```

그 이상(팔로우 피드, DM, 포인트, 예측시장 등)은 **의도적으로 안 만든다.**

---

## 3. 제품 철학

| 원칙 | 의미 |
|------|------|
| **작게 시작** | Issue 콘텐츠 품질 + 가벼운 참여만 검증 |
| **AI는 이슈 제작자** | 수집·구조화·질문 설계는 워커 파이프라인; 요청마다 실시간 LLM 금지(기존 아키텍처 유지) |
| **참여는 가벼움** | 버튼 하나. 강요된 찬반·가짜 논쟁 만들지 않음 (`participation_suitable` 등) |
| **공유 지능 우선** | Common Intelligence First — 한 번 만든 Issue를 많은 사용자가 재사용 |
| **품질 > 양** | 일일 Issue 상한(기존 Signal cap 정신과 동일) |
| **증거·과장 금지** | 확인/해석/루머 구분은 가능하면 유지; 클릭베이트만으로 참여 유도하지 않음 |

### MVP에 넣지 않는 것

- 복잡한 팔로우 / DM / 친구
- 포인트 경제 / 과도한 게이미피케이션
- 실물 머니 / Prediction Market
- 복잡한 reputation
- (전환 초기) Brief·캘린더·워치리스트를 **삭제**하는 일 → **숨김·Defer**이 기본

## 4. 현재 자산과의 관계 (재사용 관점)

이미 있는 뼈대는 새 제품의 **공급망**이다. 버리는 것이 아니라 **역할을 바꾼다.**

| 기존 | 전환 후 역할 (의도) |
|------|---------------------|
| Providers + ingest | Information 수집 (범위는 점진 확장 가능) |
| cheap_filter → cluster → analyze | AI Issue 생성 퍼널 (프롬프트·스키마 MODIFY) |
| Signal + quality + daily cap | Issue 단위로 재해석·확장 (테이블 확장 / 어댑터 API 가능) |
| `/signals` API·React 피드 | Issue Feed·Card로 UI 재구성; 구 API는 당분간 병행 |
| device / settings / push / cost | 유지 |
| Brief / calendar / watchlist | MVP 홈에서 **비활성·숨김**; 코드·데이터는 보존 |

자세한 Keep/Modify/Defer: `02-keep-modify-remove.md`.  
도메인·API·UI·DB·파이프라인·비용·범위: `03`–`10`.  
실행 순서: `11-implementation-plan.md`.

## 5. 한 장으로 보는 목표 아키텍처

```text
[Sources: X / News / …]
        ↓
[Worker ingest + pipeline]  ← LLM은 여기만 (클러스터 단위)
        ↓
[Issue (+ optional participation options)]
        ↓
[API: feed / detail / participate / comments]
        ↓
[App: Issue Card Feed → 참여 → 결과·댓글]
```

사용자 요청 경로에서는 외부 소스·LLM을 호출하지 않는다 (기존 Common Intelligence First 유지).

## 6. 성공 기준 (MVP Done)

사용자가 앱을 열었을 때:

1. 금융 대시보드 없이 **이슈 카드**를 바로 이해한다.
2. **한 번의 탭**으로 의견을 남긴다.
3. **참여 수·비율·댓글**을 본다.
4. 위 루프가 **팔로우/머니/예측시장 없이** 동작한다.

북극 지표(설계용):  
`Participation Rate = 참여자 수 / 이슈를 본 사람 수`
